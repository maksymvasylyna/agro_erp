# Event Assistant — запрошення на навчання та події

Застосунок Flask: контакти → створення заходу → вибір запрошених → підтвердження реальної email-розсилки → персональні відповіді → звіт.

## Основний процес

1. Додайте контакт з реальною email-адресою вручну або з CSV/XLSX/PDF.
2. Натисніть «Створити захід», внесіть дату, місце, опис і оберіть запрошених.
3. Після збереження відкриється сторінка «Підтвердження розсилки» з адресами. Жоден лист не буде надіслано без натискання «Підтвердити та надіслати».
4. Кожен учасник одержує особистий лист із двома варіантами — «Беру участь» і «Не зможу». Посилання відкриває приватну сторінку; отримувач підтверджує вибір окремою кнопкою. GET-запити не змінюють статус, тому поштові сканери не можуть відповісти замість користувача.
5. Звіт показує «Підтвердив», «Відмовився», «Очікуємо», «Не надіслано» або «Помилка відправлення».
6. Кожне прийняте Resend запрошення зберігається, а повторні запуски пропускають уже надіслані контакти. За помилки можна повторити спробу для невідправлених адрес.

Успішне API-відправлення означає прийняття Resend до доставки, а не гарантоване потрапляння до папки «Вхідні». Для delivered/bounced потрібні вебхуки Resend.

## Render → Environment

| Назва змінної | Значення |
| --- | --- |
| ADMIN_PASSWORD | Пароль організатора |
| SECRET_KEY | Довга випадкова строка для підписування сесій Flask |
| COOKIE_SECURE | 1 для HTTPS |
| RESEND_API_KEY | Дійсний секретний ключ Resend з правом Sending access, починається з re_ |
| TEST_RECIPIENT_EMAIL | Адреса акаунта Resend, поки використовується onboarding@resend.dev |
| EMAIL_FROM | Необов'язково; за замовчуванням Event Assistant <onboarding@resend.dev> |
| PUBLIC_BASE_URL | Необов'язково; за замовчуванням https://event-assistant-demo.onrender.com |
| DATABASE_URL | PostgreSQL для постійного збереження; без нього тимчасова SQLite |

Назви змінних залишайте латинкою без перекладу. API-ключ не надсилайте у чат та не комітьте в GitHub. Якщо Resend повідомляє «API key is invalid», створіть новий API-ключ на сторінці Resend → API Keys та замініть лише значення RESEND_API_KEY в Render. Після Save only потрібен новий деплой, щоб процес узяв нове значення.

Поки EMAIL_FROM не змінений із onboarding@resend.dev, відправляти можна тільки на email свого акаунта Resend. У коді це додатково перевіряється через TEST_RECIPIENT_EMAIL; це технічне обмеження, не окремий тестовий режим.

Щоб запрошувати будь-яких учасників, у Resend → Domains додайте і підтвердьте власний домен (додайте DNS-записи, які покаже Resend) та задайте EMAIL_FROM, наприклад Events <events@your-verified-domain.com>. Для відправлення однією дією встановлено обмеження 50 адресатів.

## Зберігання даних

Без DATABASE_URL застосунок використовує SQLite у /tmp. У безкоштовному Render файлову систему не можна вважати постійним сховищем: деплой, рестарт чи засинання можуть стерти контакти, події та токени посилань. Для справжньої експлуатації підключіть PostgreSQL і резервне копіювання, обмежте доступ до контактів і дотримуйтеся вимог щодо персональних даних. Вигадані контакти більше не створюються на старті.

## Ізоляція проєкту

Наразі Event Assistant працює в технічно ізольованій Git-гілці event-assistant-demo репозиторію AgroERP, щоб не змінювати AgroERP main. В інтерфейсі немає симуляцій, тестових кнопок або окремих тестових заходів. Надалі проєкт доцільно перенести в власний репозиторій.

## Локальні тести

    pip install -r requirements.txt
    python -m unittest discover -s tests -v
